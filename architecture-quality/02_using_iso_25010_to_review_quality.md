# ISO/IEC 25010: 빠뜨린 품질을 찾는 기준

## 1. 품질 모델은 질문을 빠뜨리지 않기 위한 도구이다

- **ISO/IEC 25010은 제품 품질을 특성과 하위 특성으로 나누어 요구사항 명세와 평가에 사용하는 참조 모델이다.**
- 성능과 보안처럼 익숙한 항목 외에 복구성, 상호운용성과 테스트 용이성도 검토하게 한다.
- 같은 용어로 요구를 논의하고 설계 결정이 어떤 품질에 영향을 주는지 설명할 수 있다.
- 모든 특성을 요구사항으로 만들거나 같은 수준으로 높이라는 뜻은 아니다.
- 이 문서는 제품 품질 특성이 아홉 개인 ISO/IEC 25010:2023을 기준으로 한다.

## 2. 아홉 가지 특성을 설계 질문으로 바꾼다

| 품질 특성 | 확인할 질문 | 관련 설계의 예시 |
| :--- | :--- | :--- |
| 기능 적합성 · Functional Suitability | 필요한 기능을 빠짐없이, 정확하고 적절하게 제공하는가? | 업무 규칙, 계산 검증과 기능 범위를 확인한다. |
| 성능 효율성 · Performance Efficiency | 필요한 시간과 처리량을 자원 한도 안에서 만족하는가? | 처리 경로, 저장소 접근과 동시 실행을 설계한다. |
| 호환성 · Compatibility | 다른 시스템과 공존하고 정보를 주고받을 수 있는가? | 연동 계약, 데이터 형식과 공유 자원을 검토한다. |
| 상호작용 역량 · Interaction Capability | 사용자가 기능을 이해하고 필요한 작업을 수행할 수 있는가? | 오류 방지, 사용자 지원과 다양한 사용 환경을 고려한다. |
| 신뢰성 · Reliability | 필요한 동안 기능을 제공하고 장애에도 견디거나 복구할 수 있는가? | 장애 격리, 이중화와 복원 절차를 검토한다. |
| 보안성 · Security | 정보와 권한을 보호하고 행위를 추적할 수 있는가? | 인증, 인가, 데이터 보호와 감사 기록을 설계한다. |
| 유지보수성 · Maintainability | 분석, 수정과 테스트를 얼마나 쉽게 수행할 수 있는가? | 모듈 경계, 의존성과 테스트 구성을 검토한다. |
| 유연성 · Flexibility | 요구, 부하와 환경이 바뀔 때 적응하거나 확장할 수 있는가? | 확장 단위, 환경 의존성과 교체 경계를 검토한다. |
| 안전성 · Safety | 사람, 재산이나 환경에 위해를 줄 수 있는 상태를 피하는가? | 위험 감지, 안전한 정지와 통합 시의 위험을 검토한다. |

- 한글 명칭은 설명을 위한 표기이며 원문의 영어 명칭을 함께 확인한다.
- 표의 설계는 검토할 후보이며 특정 품질을 자동으로 보장하는 해법은 아니다.
- 요구사항에서 기능과 품질을 나누는 관점과 제품의 기능 적합성을 평가하는 관점은 함께 사용할 수 있다.

## 3. 넓은 특성을 구체적인 검토 항목으로 나눈다

- 안정적이어야 한다는 말만으로는 장애를 막으려는지 복구 시간을 줄이려는지 알기 어렵다.
- 하위 특성까지 구체화한 뒤 필요한 상황과 수준을 정한다.

| 상위 특성 | 구체적으로 볼 항목 | 확인할 내용 |
| :--- | :--- | :--- |
| 성능 효율성 | 응답 시간, 자원 사용과 처리 용량 | 어떤 부하에서 시간이 늘고 어떤 자원이 한계에 도달하는가? |
| 신뢰성 | 가용성, 장애 허용성과 복구성 | 기능을 제공할 수 있는가, 일부 장애를 견디는가, 얼마나 빨리 복구하는가? |
| 보안성 | 기밀성, 무결성과 책임 추적성 | 누가 볼 수 있는가, 변경을 보호하는가, 행위자를 확인할 수 있는가? |
| 유지보수성 | 모듈성, 분석·수정·테스트 용이성 | 변경 영향이 어디까지 퍼지고 원인 분석과 검증이 얼마나 어려운가? |
| 유연성 | 적응성과 확장성 | 실행 환경이나 부하가 바뀔 때 어떤 부분을 변경하거나 늘려야 하는가? |

- 이 모델에서 가용성은 신뢰성의 하위 특성이다.
- 가용성과 복구성은 관련되지만 같은 목표는 아니다. 긴 중단을 드물게 겪는 것과 짧은 중단을 자주 겪는 것은 업무 영향이 다를 수 있다.
- Security와 Safety도 구분한다. 접근 권한이 올바르더라도 시스템 오동작으로 물리적 위해가 발생할 수 있다.
- 분류를 마쳤다면 조건과 판정 기준을 요구사항에 추가해야 한다.

## 4. 분류와 목표값을 혼동하지 않는다

| 표준 | 주로 답하는 질문 |
| :--- | :--- |
| ISO/IEC 25010:2023 | 어떤 제품 품질을 검토할 것인가? |
| ISO/IEC 25023:2016 | 제품 품질을 어떤 측정항목과 방법으로 평가할 것인가? |
| ISO/IEC 25030:2019 | 품질 요구사항을 어떻게 도출하고 정의·관리할 것인가? |

- **표준의 품질 분류나 측정항목이 서비스의 목표 응답 시간과 가용률까지 정해 주지는 않는다.**
- 합격 기준은 사용자 요구, 업무 손실, 적용 제약과 비용을 바탕으로 정한다.
- ISO/IEC 25023:2016은 2011년 품질 모델을 바탕으로 하므로 2023년 모델의 항목과 사용할 때 대응 관계를 확인한다.
- 측정항목을 참고하더라도 실제 적용 대상, 집계 방식과 판정 조건을 명시해야 한다.

## 5. 판본을 명시하고 필요한 범위를 선택한다

| 항목 | 2011년판 | 2023년판 |
| :--- | :--- | :--- |
| 제품 품질 특성 수 | 여덟 개이다. | 아홉 개이다. |
| 사용자와의 상호작용 | 사용성 · Usability | 상호작용 역량 · Interaction Capability |
| 환경 변화 대응 | 이식성 · Portability | 유연성 · Flexibility |
| 안전성 | 독립된 최상위 특성으로 구분하지 않는다. | Safety가 추가되었다. |

- 이름만 바뀐 것이 아니라 하위 특성의 구성도 변경되었다.
- 2011년판에 함께 있던 사용 중 품질 모델은 ISO/IEC 25019:2023에서 다룬다.
- 서로 다른 판본의 용어를 섞으면 같은 이름으로 다른 범위를 논의할 수 있으므로 기준 판본을 밝힌다.
- 모든 하위 특성을 나열하기보다 시스템에 관련된 항목과 추가 확인이 필요한 항목을 골라 활용한다.

## 6. 레퍼런스

- [ISO/IEC 25010:2023 — Product quality model](https://www.iso.org/standard/78176.html): 제품 품질 모델의 목적과 아홉 가지 특성으로 이루어진 구성을 설명한다.
- [ISO/IEC 25023:2016 — Measurement of system and software product quality](https://www.iso.org/standard/35747.html): 제품 품질의 측정항목과 적용 방법을 설명한다.
- [ISO/IEC 25030:2019 — Quality requirements framework](https://www.iso.org/standard/72116.html): 품질 요구사항의 도출, 정의와 관리 체계를 설명한다.
- [ISO/IEC 25019:2023 — Quality-in-use model](https://www.iso.org/standard/78177.html): 사용 맥락에서의 품질을 다루는 모델을 설명한다.
