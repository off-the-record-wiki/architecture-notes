# 대규모 트래픽: 요구사항에서 대응 우선순위 찾기

## 1. 피크 시간에 사용자에게 보장할 결과를 정한다

- **업무 완료 조건을 기준으로 요구사항 조정과 기술적 대응을 함께 비교한다.**
- 요청 접수, 결과 확정과 후속 작업의 완료 조건을 업무 담당자와 확인한다.
- 요구사항 협의와 기술 검증을 병행한다. 합의된 요구를 유지하는 증설·최적화는 정책 변경보다 먼저 진행할 수 있다.
- 진행 중인 장애에서는 복구와 피해 억제를 우선한다.

| 확인할 질문 | 결정할 사항 |
| :--- | :--- |
| 성공 응답은 무엇을 보장하는가? | 접수와 업무 결과 확정을 구분한다. |
| 어떤 작업이 늦어지면 사용자나 업무에 손해가 생기는가? | 즉시 완료할 작업과 지연 가능한 작업의 완료 기한을 정한다. |
| 중복 실행, 처리 누락과 결과 변경을 어디까지 허용하는가? | 각 단계에서 금지할 결과와 오류 발생 시 처리 규칙을 정한다. |
| 이용 기회의 공정성을 어떻게 보장해야 하는가? | 이용 시간과 대상을 나눌 수 있는 범위를 정한다. |
| 어떤 조건이 계약·정책으로 고정되어 있는가? | 변경할 수 없는 조건과 협상할 조건을 구분한다. |

- 조건마다 출처와 합의 여부를 남기고, 미확인 항목은 확인할 담당 역할을 정한다.
- 완료 조건과 기한을 대안 비교와 검증에 공통으로 사용한다.

## 2. 요청이 몰리는 구간과 처리 비용을 확인한다

- 기존 시스템은 요청 로그, 처리 시간과 자원 사용량을 같은 시간 구간으로 맞춰 본다.
- 신규 시스템은 사용자 수, 요청 횟수와 집중 시간을 가정해 부하 실험으로 확인한다.

| 확인할 자료 | 판단할 사항 |
| :--- | :--- |
| 시간 구간별 요청 수, 증가 속도와 피크 지속 시간 | 요청이 몰리는 구간을 찾고, 분산 효과와 필요한 처리 용량을 추정한다. |
| 기능별 호출 수, 처리 시간과 자원 사용량 | 자원을 많이 쓰는 기능 중 실행 시점을 옮길 후보를 찾는다. |
| DB 대기, 연결 풀 대기와 외부 호출 지연 | 어느 구간이 전체 처리를 제한하며 서버 증설로 개선할 수 있는지 판단한다. |
| 업무 시도별 요청 횟수와 재시도 비율 | 실제 수요 외에 새로고침·재시도로 늘어나는 부하를 찾는다. |

- 짧은 피크가 가려지지 않도록 집계 간격을 정하고, 요청 비율과 데이터 규모를 기록한다. 예상값과 실측값을 구분한다.
- 대기가 늘어난 구간의 호출 흐름과 자원 경합을 확인한다.
- 해당 구간을 개선했을 때 전체 처리량과 지연이 나아지는지 검증해 병목을 판단한다.

## 3. 이용 시간과 대상을 나눌 수 있는지 판단한다

- 정책 변경이 가능하면 이용 시간, 대상과 접수 기간의 조정안을 검토한다.
- 대상만 나눠 같은 시각에 같은 자원을 사용하면 부하는 그대로이므로 집단별 이용 시간과 접근 규칙을 함께 정한다.

| 조정안 | 먼저 확인할 조건 | 기각하거나 보완할 상황 |
| :--- | :--- | :--- |
| 이용 시간을 나눈다. | 시간대별 참여 규모와 운영 가능 시간 | 특정 시간대에 다시 몰리거나 참여하지 못하는 사용자가 생긴다. |
| 이용 대상을 나눈다. | 집단별 규모, 자격 확인과 자원 배분 규칙 | 앞선 집단이 자원을 소진하거나 예외 처리가 늘어난다. |
| 접수 기간을 늘린다. | 조기 참여의 이점과 마감 직전 참여 이유 | 시작·마감 시점의 집중이 유지된다. |

- 균등한 분산을 가정하지 않고 집단별 요청량과 시간 중첩을 반영해 피크를 다시 추정한다.
- 참여 기회를 놓친 사용자의 후속 이용 경로와 안내·예외 처리 담당을 정한다.
- **피크 감소량, 이용 기회의 차이와 추가 운영 시간을 함께 비교한다.**

## 4. 즉시 처리 경로에서 옮길 작업을 고른다

- 응답까지 수행하는 작업과 외부 호출을 아래 기준으로 분류한다.
- 비동기로 분리해도 피크에 실행하면 공유 자원 부하는 남는다. 실행 시점과 동시 처리 한도를 따로 정한다.

| 처리 시점 | 분류 기준 | 결정할 사항 |
| :--- | :--- | :--- |
| 사전 처리 | 미리 처리하고 사용 시점에 유효성을 확인할 수 있다. | 유효 기간, 무효화와 재확인 범위 |
| 즉시 처리 | 미루면 성공 응답에서 약속한 결과를 보장할 수 없다. | 확정할 데이터, 동시 변경과 중복 요청의 처리 규칙 |
| 후속 처리 | 합의한 기한까지 지연해도 업무 목표를 충족한다. | 완료 기한, 상태 관리 주체와 재처리·취소 규칙 |

- 접수 성공 응답 전에 약속한 내구성 수준으로 작업을 저장한다.
- 상태를 소유할 구성요소, 결과 전달 인터페이스와 사용자 안내를 정한다. 만료·실패 시 행동도 포함한다.
- 중복 요청 식별자의 범위·보관 기간을 정하고, 동시 요청과 장애에서도 중복 반영을 막을 [멱등 처리](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)를 설계한다.
- 처리 기록과 실제 변경의 일관성을 원자적 처리나 복구 절차로 확보하고, 외부 호출의 중복 방지 범위도 확인한다.
- 신규 유입과 재처리를 포함한 작업량이 기한 내 처리 용량을 넘으면 연기 범위나 용량을 조정한다.
- **즉시 처리 비용의 감소와 중간 상태·복구 절차의 증가를 함께 비교해 분리 여부를 결정한다.**

## 5. 기존 요구 유지안과 조정안을 비교해 합의한다

- 기존 구조·정책 유지, 부분 개선, 요구사항 조정과 기술적 확장을 비교하거나 조합한다.
- 같은 업무 수요와 필수 조건에서 대안별 요청 시점과 기능 구성을 반영한다.

| 비교할 항목 | 제시할 근거 | 합의할 역할 |
| :--- | :--- | :--- |
| 사용자 결과 | 이용 가능한 시간, 최대 대기 시간, 완료 기한과 참여하지 못하는 대상 | 업무·제품 담당자 |
| 부하 감소 | 변경 전후의 피크 요청량, 즉시 처리할 작업과 후속 작업량 | 개발·운영 담당자 |
| 구현 비용 | 변경할 기능·계약, 추가 상태·실패 경로와 개발·테스트 기간 | 개발·QA 담당자 |
| 운영 비용 | 필요한 용량, 추가 운영 시간, 예외 처리·문의 대응 업무 | 운영·고객 지원·예산 담당자 |

- 비용·기간의 추정 근거를 제시하고 후속 처리와 운영 비용까지 포함한다.
- 필수 조건을 만족하는 안이 없으면 업무 담당자와 범위·기한을, 자원 결정권자와 예산·인력을 재협의한다.
- 채택 상태, 선택 이유, 감수할 비용과 담당 역할을 기록한다. 변경 사항은 사용자 안내와 운영 절차에 반영한다.

## 6. 병목에 맞는 기술을 선택하고 업무 완료까지 검증한다

- 확인한 병목에 맞춰 기술을 선택하고, 요구사항 조정안이 있으면 변경 후 부하도 비교한다.

| 수단 | 적용 조건 | 확인할 한계 |
| :--- | :--- | :--- |
| [작업 큐](https://learn.microsoft.com/en-us/azure/architecture/patterns/queue-based-load-leveling) | 접수와 완료를 나누고 처리 속도를 조절할 수 있다. | 큐 자체는 처리 용량을 늘리지 않는다. 지속적인 유입이 처리량을 넘으면 적체가 증가한다. |
| [캐시](https://aws.amazon.com/builders-library/caching-challenges-and-strategies/) | 적중률이 충분하고 갱신·무효화로 요구하는 최신성을 지킬 수 있다. | 빈 캐시, 장애와 동시 만료 때 원본으로 몰리는 요청을 감당하거나 제한해야 한다. |
| 서버 증설 | 증설 대상이 병목이고 추가 자원으로 처리량을 높일 수 있다. | 수평 확장의 부하 분배, 수직 확장의 자원 효과, DB·외부 시스템 한도와 확장 시간을 확인한다. |

- 작업 큐는 접수한 작업을 보관하고 접속 대기열은 입장을 제어한다.
- 작업 큐에는 소비자의 처리 한도, 저장 용량·보관 기간과 한도 초과 시 접수 정책을 정한다.
- 검증할 기능, 부하·장애 범위, 측정 구간·집계 방식과 합격 기준을 정한다. 부하에는 요청 구성·규모·지속 시간을 포함한다.
- 접수 응답 시간과 최종 완료 시간을 따로 측정한다.

| 검증할 상황 | 확인할 결과 |
| :--- | :--- |
| 예상 피크와 이용 시간 중첩 | 시간대·집단별 대기 시간, 오류율과 업무 완료율의 기준을 충족한다. |
| 외부 연동 지연과 재시도 증가 | 허용 지연·실패율과 중복·누락 방지 조건을 지킨다. |
| 후속 작업 적체와 일부 실패 | 기한 내 완료율을 지키고, 기한 초과·영구 실패를 식별해 복구·취소한다. |
| 피크 이후의 신규 유입 | 신규 요청의 지연·오류율을 지키면서 정한 시간 안에 적체를 해소한다. |

- 결과에는 추정·실험·운영 관측 여부, 검증 조건과 운영 환경과의 차이를 남긴다.
- 필수 조건을 위반할 수 있는 가정은 채택 전에 검증한다. 채택 후 확인할 항목은 담당 역할, 확인 시점과 기준 미달 시 조치를 정한다.
- 부하가 검증 범위를 벗어나거나 완료 기한·비용 기준을 넘으면 정책과 기술 선택을 재검토한다.
